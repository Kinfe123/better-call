# Concepts

Better Call is built around a small set of composable primitives. Understanding how they fit together makes everything else predictable.

An **endpoint** is the fundamental unit — a path, a set of options, and a handler. Endpoints can be called directly as functions or mounted on a router and served over HTTP. This dual-invocation model means your business logic doesn't have to change depending on the calling context.

A **router** collects endpoints and exposes a single `handler` function you pass to any Fetch-compatible server. The router handles matching, error serialization, and optional middleware that applies across matching routes.

**Middleware** lets you inject shared context — authentication data, database connections, tracing — into the handler's `ctx.context` object. Every endpoint that declares a middleware in its `use` array gets the middleware's return value merged into context.

The **RPC client** mirrors the router's type on the browser side. Because both sides share the same TypeScript types, path autocompletion, request body shapes, and response types are inferred automatically.
