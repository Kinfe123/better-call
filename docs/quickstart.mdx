# Quickstart

This guide takes you from a fresh install to a running server with a typed client in a few steps. You will define an endpoint, mount it on a router, serve it with Bun, and call it from a client with full type safety.

## 1. Install dependencies

```bash
pnpm add better-call zod
```

## 2. Define an endpoint

Endpoints are the core building block. Each one has a path, options (including an HTTP method and optional schema), and a handler function.

```ts
// item.ts
import { createEndpoint } from "better-call";
import { z } from "zod";

export const createItem = createEndpoint(
  "/item",
  {
    method: "POST",
    body: z.object({
      id: z.string(),
    }),
  },
  async (ctx) => {
    return {
      item: {
        id: ctx.body.id,
      },
    };
  }
);
```

You can already call this endpoint as a plain async function — no server needed:

```ts
const result = await createItem({ body: { id: "123" } });
console.log(result.item.id); // "123"
```

## 3. Mount on a router and serve

Pass your endpoints to `createRouter` to get a `handler` you can hand directly to Bun (or any Fetch-compatible server):

```ts
// server.ts
import { createRouter } from "better-call";
import { createItem } from "./item";

const router = createRouter({ createItem });

Bun.serve({
  fetch: router.handler,
});
```

Start the server:

```bash
bun server.ts
```

## 4. Call from the client

Import the router type (not the value) and pass it as a generic to `createClient`. The client is fully typed — it knows every path, the shape of each request body, and the shape of each response.

```ts
// client.ts
import { createClient } from "better-call/client";
import type { router } from "./server";

const client = createClient<typeof router>({
  baseURL: "http://localhost:3000",
});

const result = await client("/item", {
  body: { id: "123" },
});

console.log(result.item.id); // "123"
```

That's the full loop: define, serve, and call with complete type safety from server to client.

From here, read [Endpoints](/docs/concepts/endpoints) to understand paths, parameter types, and validation options. [Middleware](/docs/concepts/middleware) shows you how to share context across handlers, and [Router](/docs/concepts/router) covers router options like base paths and error handling.
